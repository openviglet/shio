## Block H — The Agent Gateway (agent-native reorientation, SH74)

- **SH77** — **Context pack** (`GET /api/v2/agent/context`). The one call that replaces a session of exploration (design law P2): content **model** (post-types with fields, reusing the SH11 `ShCdaSchemaField` shape so an agent learns one field shape across the product), **sitemap** as a flat depth-first row list keyed by path, derived **conventions**, a **digest**, and a **budget** report. Composition, not a new contract (P10): the model comes from the existing `ShCdaMapper` and site visibility reuses the SH2 per-site token allow-list, so the pack can never show content the CDA would hide from the same credential. [ShAgentContextService](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentContextService.java) + [ShAgentContext](../shio-app/src/main/java/com/viglet/shio/api/agent/dto/ShAgentContext.java) (one document type, nested records) + [ShAgentContextSection](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentContextSection.java) + [ShAgentProperties](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentProperties.java) (`shio.agent.context.*`: default/max budget, default depth, max nodes). Every parameter is optional — the single-site case is a bare GET. **Determinism is load-bearing, not cosmetic:** the `digest` (SHA-256 over the canonical terse body, `c:` + 12 hex) is what lets an agent skip re-reading, so every collection is explicitly sorted (types by name, sites by name, folders by position→name→id, posts by title→id) and the digest deliberately **excludes** the budget/measurement lines so it tracks content only and is identical for the JSON and terse renderings. Folder posts are deduped **draft-preferred**, matching the CDA's `/list`, so the two views of a folder never disagree. **Honest truncation:** only the sitemap is budget-gated (a partial model is not a smaller answer, it is a wrong one — an agent that sees 6 of 9 types invents the other three), cuts are reported with a resumable `from=` cursor, and `truncated` with a `null` cursor is the explicit "nothing fit, raise the budget" signal. Conventions are **derived from the instance** (managed/system type counts, unused types, the DRAFT-then-publish rule, path addressing, multi-site hint) — author-written conventions arrive with SH114. Two new grouped count queries on `ShPostUnifiedRepository` count `distinct p.id` (the unified model stores up to two rows per post) — see the SH22 note below. 21 tests ([ShAgentContextTest](../shio-app/src/test/java/com/viglet/shio/api/agent/ShAgentContextTest.java)). Concept: [specs/SH74-agent-native-cms.md](specs/SH74-agent-native-cms.md) §4.3.
- **SH78** — **Token-lean responses.** The mechanics behind law P3. [ShTokenBudget](../shio-app/src/main/java/com/viglet/shio/api/agent/ShTokenBudget.java) (≈4-chars-per-token estimate, `tryAdd` refuses a chunk without charging it so output is always cut at a row boundary, `overBudget` reports a mandatory-section overrun instead of hiding it), [ShTerse](../shio-app/src/main/java/com/viglet/shio/api/agent/ShTerse.java) (`format=terse` line grammar: one quoting rule — quote iff empty or containing a space/quote — with absent attributes and zero counts omitted entirely), [ShAgentContextTerse](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentContextTerse.java) (also the canonical digest input, so what is measured is exactly what is emitted), `include=` section projection with a teaching 400 on an unknown section, and [ShAgentTokenHeaderFilter](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentTokenHeaderFilter.java) stamping `X-Shio-Est-Tokens` on every `/api/v2/agent/*` response (measured on the serialized body, so it covers both encodings and cannot drift). **Three findings, each now a test:** (1) *the terse win is per-row, not per-payload* — JSON pays for braces and every key name on every row while terse states the shape once in the verb, so the saving scales with row count (~25–35% per row) and is diluted on a small pack by fixed prose; the assertion therefore measures the **marginal** cost of a row, which is what would catch a node row being "enriched" back into a blob. (2) The residual per-row cost is dominated by the **36-char UUID**, not by the encoding — which makes **SH79 path addressing the larger token lever**, now quantified rather than assumed (→ new SH121). (3) Agent JSON was itself paying for `"folders":0,"posts":0` and four explicit `null`s on every row; `@JsonInclude(NON_DEFAULT)` on the agent DTOs applies the same "don't pay for what you don't say" rule to JSON, so the comparison is against a lean alternative rather than a rigged one (→ new SH125 to make it policy). **Two bugs the tests caught in the implementation itself:** an unbounded budget short-circuited `tryAdd` *without charging*, so `estTokens`/`X-Shio-Est-Tokens` silently under-reported the entire sitemap on every `budget=0` call; and conventions were charged **after** the sitemap gate opened, letting the walk admit rows that the later charge pushed over the ceiling the caller had asked for. Both fixed with regression tests. A misleading `omittedNodes` count was **removed** rather than fixed — the walk stops at the budget so it cannot know how much remains, and the only number it had ("1 more") understated the truth; the scale of what is left is already derivable from the `folders`/`posts` counts on each emitted folder row. 9 tests ([ShTerseAndBudgetTest](../shio-app/src/test/java/com/viglet/shio/api/agent/ShTerseAndBudgetTest.java)) + the SH77 suite. **Scope note:** per-field `fields=` projection on *content* reads is **not** in this task — there are no content reads on the agent surface until SH79/SH83, so it is tracked as SH123. Concept: [specs/SH74-agent-native-cms.md](specs/SH74-agent-native-cms.md) §4.4.
- **SH122** — **Build-time guard for the `@TenantId` JOINED-join hazard — and three production bugs it uncovered.** [ShTenantJoinHazardTest](../shio-app/src/test/java/com/viglet/shio/tenant/ShTenantJoinHazardTest.java) characterizes the failure by *executing* each query form, and that mattered because reasoning got it wrong twice. The first hypothesis was "only projections and `GROUP BY` are affected", since shipped queries navigated `p.shPostType.name` in a `WHERE` clause with green tests. Executing the predicate form showed it fails identically — the generated SQL explains why: Hibernate joins **only the subclass table** (`join "ShPostType" spt1_0 on …`) and still emits `and spt1_1.tenant_id = ?` against a root alias it never declared. An explicit `join` does not rescue it either. So the rule is the widest one: **never navigate past `.id`** of an `ShObject`-subclass association, in any clause. **The green tests were green because they never reached the finder** — which means three shipped paths were broken in production and nothing said so: `GET /api/v2/cda/query?siteId=&postType=` (a *documented* SH1 endpoint), and `GET /api/v2/cda/search?q=&siteId=` for any site with `searchablePostTypes` configured (SH52) — the existing search tests passed because no fixture configured one. Fixed by filtering on the post-type **id**: `ShCdaService.pageBySiteAndType` resolves the public `?postType=<name>` to an id first (unknown name → empty page, never a 500), and `searchablePostTypeNames` became `searchablePostTypeIds`; four repository finders were re-keyed. The identical fix had been sitting three lines above them in the same file since SH61, which is precisely the argument for a guard rather than a comment. [ShTenantJoinLintTest](../shio-app/src/test/java/com/viglet/shio/tenant/ShTenantJoinLintTest.java) scans repository sources — both `@Query` strings and derived method names — and fails the build on any navigation past `.id`, skipping comments (so the rule can be documented without tripping itself) and native queries (no tenant predicate is added to those). Its own regexes are self-tested, because a lint that silently matches nothing is worse than none: word boundaries turned out to be useless on **both** sides of a derived name — the association is glued to `By`/`And` (no boundary before) and the next property starts with a capital, so `Id\b` does not hold in `_IdAndState` (which would have flagged every safe finder). 4 new tests + 6 characterization tests; regression cover in [ShCdaTenantJoinRegressionTest](../shio-app/src/test/java/com/viglet/shio/api/cda/ShCdaTenantJoinRegressionTest.java). → §XIV.4
- **SH124** — **Cost instrumentation on the delivery path.** `X-Shio-Est-Tokens` now covers `/api/v2/cda/*` as well as `/api/v2/agent/*` — instrumenting only the agent namespace would have measured the cheap half of an agent's traffic and missed the expensive one, leaving SH112/SH113 blind to the reads that actually dominate. `ShAgentTokenHeaderFilter` → [ShEstTokensHeaderFilter](../shio-app/src/main/java/com/viglet/shio/api/agent/ShEstTokensHeaderFilter.java) (the name was surface-specific; the concern is not), registered once for both patterns at `LOWEST_PRECEDENCE - 30` — deliberately **outside** the SH3 ETag filter, so a conditional `304` is measured as the zero-byte response it really is. That ordering is what will let SH116's claim ("an unchanged context costs nothing") show up as a number rather than an assertion. → §XIII.2
- **SH125** — **Null/default omission as policy, with the counter-rule.** Nulls are always waste (`"url": null` and an absent `url` say the same thing), so every agent-owned DTO omits them — enforced by [ShAgentJsonLeanTest](../shio-app/src/test/java/com/viglet/shio/api/agent/ShAgentJsonLeanTest.java), which serializes real responses and fails on any `:null`. **The interesting half is what the policy refuses to do.** A blanket `NON_DEFAULT` — the obvious "make it smaller" move, and what the task originally proposed — would have stripped the `false` entries from the manifest's `features` map and `truncated: false` from a budget report. Those are not defaults, they are *answers*: an absent feature flag sends a caller probing (the exact cost the manifest exists to remove) and a missing `truncated` reads as "unknown". So the rule is **NON_NULL as the baseline, NON_DEFAULT only where a default is genuinely uninformative** (row-shaped DTOs, where `folders: 0` on a post row says nothing) — leanness is never a licence to drop an answer, and both counter-cases are pinned by tests. Two scoping decisions recorded rather than glossed: (1) **the CDA is untouched** — its TypeScript mirror declares nullable fields as `string | null`, *not* optional, so omitting a null would turn a declared `null` into `undefined` and break typed consumers; leaning the delivery path needs a coordinated SDK type change (→ new SH127). (2) The context pack's `model` section therefore still ships the CDA shape's nulls, which is the measurable price of composing over a frozen contract (P10) — asserted by a characterization test so it stays visible instead of reading as an oversight. An earlier draft of this test read whatever the shared test database happened to hold and passed or failed by class ordering; it now owns its fixture, because a leanness rule that only holds in one test order is not a rule. → §XIII.2
- **SH126** — **`shio context` CLI.** Completes SH77's stated surface: `shio context [--format terse|json] [--site] [--include] [--depth] [--budget] [--from] [--out]`, over a new [ShioAgentClient](../cli/src/agent-client.mjs) (console Basic auth — the pack reports the *authoring* view, so it is an admin read; kept separate from `ShioAdminClient`, which hard-codes the `/api/v2/post-type` prefix). Two deliberate choices: **`terse` is the default here** (unlike the endpoint, whose default stays JSON — the caller of a CLI is an agent), and the body is streamed through as **text, never parsed and re-serialized**, because the pack's digest is computed over exactly those bytes and reformatting would break `--out` diffs. `--out` writes a committable artifact a later session or a reviewer can diff; an unknown `--format` is rejected with the allowed set in the message, mirroring the server's teaching-error contract (SH80). 8 new `node:test` cases ([context.test.mjs](../cli/test/context.test.mjs)) incl. byte-for-byte passthrough, flag forwarding, blank-flag omission, and no artifact written on an HTTP failure; CLI suite 33 green. → §VIII.3
- **SH22 follow-up (found by SH77)** — **the `@TenantId` JOINED-join hazard.** A JPQL query that navigates *past the id* of an association whose target is an `ShObject` subclass (`ShSite`/`ShFolder`/`ShPostType`) makes Hibernate emit the tenant discriminator predicate against the **subclass** table alias, which carries no `tenant_id` column (it lives on the JOINED `ShObject` root) — the query dies at prepare time with `Column "spt1_1.tenant_id" not found`. Valid JPQL, invisible until runtime. Both new count queries group on the association **id** instead, which uses the FK column already on `sh_post_unified`: no join, no tenant predicate, cheaper SQL. Documented in `agents.md` → Common Issues and in `ShPostUnifiedRepository`; a build-time guard is tracked as SH122.

- **SH76** — **Agent manifest** (`GET /api/v2/agent/manifest`). The instance describing itself to a coding agent, so the dominant agent failure mode — *guessing* an endpoint, a capability or a parameter name — costs one cached call instead of a 404 and a retry (design law P2). New `com.viglet.shio.api.agent` package: [ShAgentAPI](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentAPI.java) + [ShAgentManifestService](../shio-app/src/main/java/com/viglet/shio/api/agent/ShAgentManifestService.java) over three records ([ShAgentManifest](../shio-app/src/main/java/com/viglet/shio/api/agent/dto/ShAgentManifest.java) / [ShAgentEndpoint](../shio-app/src/main/java/com/viglet/shio/api/agent/dto/ShAgentEndpoint.java) / [ShAgentLimits](../shio-app/src/main/java/com/viglet/shio/api/agent/dto/ShAgentLimits.java)). Payload: product + build version (jar `Implementation-Version`, `dev` in an IDE) + a **`protocol` revision** that versions the *agent surface shape* independently of the product; a sorted `features` map; `limits` (rate-limit bucket, default page size, cache max-age) so a client paces itself instead of learning the ceiling from a `429`; a **curated** endpoint index (16 entries, each with `purpose`, the required credential, and a runnable `example`); and `startHere` — the opening three calls, model before content. Two deliberate design calls: (1) **features are three-valued in origin but binary on the wire** — *configured* flags read the live properties (`multiTenant`, `oidc`, `webhooks`, `scheduledPublish`, `previewTokens`, `rateLimit`, `signedImageUrls`), *build* flags are constants of the artifact, and **unshipped capabilities are reported `false`, never omitted** (an absent flag sends the caller probing, which is the cost the manifest exists to remove); (2) the index is curated, not generated from the full API — it is read every session, so a token budget applies (P3), enforced by a test that fails if it grows past 30 entries. `ShApiTokenFilter` gains `/api/v2/agent` as a **third** token-authenticated prefix (after `/api/v2/cda` and `/graphql`) so a delivery key can read the manifest without a console credential — the SH2 method gate is untouched, so this widens *reads* only, and a `READ` key still gets `403` on a POST there. No security-config change: the namespace falls under the existing `anyRequest().authenticated()`, so a console session and HTTP Basic (the `shio` CLI) work too. 9 tests ([ShAgentManifestTest](../shio-app/src/test/java/com/viglet/shio/api/agent/ShAgentManifestTest.java)) assert the *contract* rather than the contents — byte-stability across calls, sorted keys, unshipped-as-`false`, every endpoint self-sufficient, the index stays small — plus 2 in `ShApiTokenFilterTest` (16 total) for the prefix widening. Concept: [specs/SH74-agent-native-cms.md](specs/SH74-agent-native-cms.md) §4.2.
- **SH80** — **Teaching errors** (RFC 9457 + `fix`/`allowed`/`didYouMean`/`example`). Design law **P6 — errors are instructions**: every field on the wire is a round trip the caller does not spend re-deriving the contract. New `com.viglet.shio.api.error` package: [ShProblem](../shio-app/src/main/java/com/viglet/shio/api/error/ShProblem.java) (immutable builder over Spring's `ProblemDetail`; `type` = `https://shio.viglet.com/errors/<slug>`; **blank/empty extensions are omitted entirely** rather than serialized as `null`/`[]`, so a response never pays for what it doesn't teach), [ShTeachingException](../shio-app/src/main/java/com/viglet/shio/api/error/ShTeachingException.java) (a domain error carries its own problem, so adding one is a constructor — not another handler), [ShDidYouMean](../shio-app/src/main/java/com/viglet/shio/api/error/ShDidYouMean.java) (commons-text Levenshtein over a case/separator-insensitive normal form, gated at `max(2, len/3)` — a wrong suggestion is worse than none — and tie-stable on the candidate order), and [ShApiExceptionHandler](../shio-app/src/main/java/com/viglet/shio/api/error/ShApiExceptionHandler.java) (`@RestControllerAdvice`; renders domain problems and enriches four framework exceptions: missing parameter, type mismatch, unreadable body, wrong verb). **Statuses are unchanged from the framework defaults — only bodies gain content** — so nothing that branches on a status code is affected. Two enrichments are worth naming: a `MethodArgumentTypeMismatchException` on an **enum** parameter returns the constants as `allowed` + the nearest match (the most common "which values does this take?" round trip), and a `405` returns the mapped verbs as `allowed`, which is what stops a caller probing verbs. The three existing post-type exceptions (`ShUnknownWidgetException`, `ShSystemPostTypeException`, `ShManagedPostTypeException`) now extend `ShTeachingException`; both throw sites load the widget catalog **on the error path only** so a 400 can teach the installed names. **The interesting finding:** nearest-string matching is silent on exactly the guess an agent is most likely to make — `RichText` is 4 edits from `Text` and further from everything else, because it is a *vocabulary* mismatch, not a spelling one. Hence [ShWidgetAliases](../shio-app/src/main/java/com/viglet/shio/api/post/type/ShWidgetAliases.java): ~90 foreign widget names from Contentful / Sanity / Strapi / Payload / JSON-schema (`richtext`, `symbol`, `reference`, `relation`, `media`, `asset`, `array`, `enumeration`, `boolean`, `portabletext`…) mapped onto the 14-widget catalog, consulted **before** the distance fallback and **only ever suggesting a target that is actually installed**. 15 tests ([ShTeachingErrorTest](../shio-app/src/test/java/com/viglet/shio/api/error/ShTeachingErrorTest.java), network-free) cover omission of empty extensions, the four teaching fields, alias translation per source platform, the typo fallback, tie determinism, the never-suggest-an-uninstalled-widget invariant, and message/detail agreement between logs and the wire. Concept: [specs/SH74-agent-native-cms.md](specs/SH74-agent-native-cms.md) §4.6.

## Block A — Headless foundation (Content Delivery API)

- **SH5** — **Per-environment keys (prod/preview).** `ShApiToken` gains an `env` ([ShApiTokenEnv](../shio-app/src/main/java/com/viglet/shio/persistence/model/token/ShApiTokenEnv.java): `PROD`/`PREVIEW`; `environment` column, `ddl-auto=update`, no migration; `null` = `PROD`). The axis is orthogonal to the SH2 `scope`: scope = *what operations*, env = *which content state*. [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) reads it, grants `ROLE_CDA_PREVIEW` for `PREVIEW` keys, and carries it in [ShApiTokenContext](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenContext.java) (new `env` component + `preview()`; back-compat 3-arg constructor defaults `PROD`). [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) replaces the hard-coded `PUBLISHED` with a per-request resolution — **`PROD` keeps the existing efficient single-state `Page` queries byte-for-byte**; **`PREVIEW` reads draft-preferred** (point lookups try `DRAFT` then `PUBLISHED` via `resolvePost`/`readStates`; listings/query/GraphQL fetch `{DRAFT,PUBLISHED}` via new `…StateIn` finders, dedup by post id keeping the `DRAFT` row, and page in memory). Driven **solely by `env`** (the SH2 `PREVIEW` *scope* stays an authz marker SH13 builds on), so there's one draft-visibility driver and REST + GraphQL (SH4) inherit it identically; the SH2 per-site allow-list still applies on every branch. `ShApiTokenAPI` persists `env`; React token editor adds an **Environment** select + description, list shows a preview badge, en/pt i18n. No-token / pre-SH5 access stays `PROD` = the SH1 behaviour. 17 tests green (`ShApiTokenFilterTest` 10 (+2), `ShCdaEnvTest` 4 (new), `ShCdaScopeTest` 3) + SH1's `ShCdaAPITest` 11 still green. **SH13** (short-lived preview tokens + in-console "preview this draft" UX) layers on this draft-visibility machinery. Spec: `docs/specs/SH5-per-environment-keys.md`.
- **SH4** — **Real GraphQL delivery schema.** [ShGraphQLSchema](../shio-app/src/main/java/com/viglet/shio/api/cda/graphql/ShGraphQLSchema.java) now builds the GraphQL schema programmatically from the content post-types (replacing the placeholder `schema.graphqls`): a `ShContent` interface carries the common post fields, each `system=0` post-type becomes an object type implementing it with a `String` field per `ShPostTypeAttr` (keyed by attr `name`), and a `ShGenericPost` fallback backs system / unmapped types (also guaranteeing the schema builds with zero content types). Names are coerced to the GraphQL grammar (invalid chars → `_`, dedup on collision). The `Query` root — `post(id)`, `postByUrl(siteId, url)`, `posts(siteId, folderId, postType, page, size)` — delegates to [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) (new `queryPosts` returns full posts with attrs; shared `queryPage`), so GraphQL **inherits SH2 per-site scoping + `PUBLISHED`-only** rather than re-implementing them — a second *shape* over the same contract, not a second contract. Served via a [ShGraphQLConfig](../shio-app/src/main/java/com/viglet/shio/api/cda/graphql/ShGraphQLConfig.java) `GraphQlSourceBuilderCustomizer.schemaFactory`. `/graphql` is now a CDA delivery surface: [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) authenticates + rate-limits it like `/api/v2/cda/**` (the SH2 GET-only gate skipped — GraphQL reads via `POST`, and the schema exposes **no `Mutation`**), and [ShSecurityConfig](../shio-app/src/main/java/com/viglet/shio/spring/security/ShSecurityConfig.java) requires `ROLE_CDA` on `POST /graphql` (was `permitAll`). Build-at-startup caveat: a new/edited post-type needs a restart to appear in the schema. Attr fields are `String` for now (strong per-widget typing awaits SH11). 8 tests green (`ShGraphQLSchemaTest` 7 incl. query-execution, `ShApiTokenFilterTest` +1 = 8) + SH1/SH2/SH3 still green. Spec: `docs/specs/SH4-cda-graphql-schema.md`.
- **SH3** — **CDA rate limiting + caching headers.** [ShCdaCacheConfig](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaCacheConfig.java) registers two servlet filters scoped to `/api/v2/cda/*`: Spring's `ShallowEtagHeaderFilter` (body-hash `ETag` + `304` on `If-None-Match`) and [ShCdaCacheControlFilter](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaCacheControlFilter.java) (`Cache-Control: public, max-age=N`, or `no-cache` when `N=0`) — both ordered after the security chain so a `401`/`403`/`429` never gets cached. [ShCdaRateLimiter](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaRateLimiter.java) is an in-memory, per-token token bucket (keyed by `ShApiToken.id`, lazy refill off a monotonic clock); [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) enforces it after auth → `429` + `Retry-After` + `X-Rate-Limit-Remaining`. - **SH43** — **Image-transform limits & security (max dims, allowed formats, signed URLs) — completes the SH25 epic.** The transform surface (SH39–42) was an open door: any caller could request arbitrary `?w=&h=&format=` combinations, pinning CPU and flooding the SH42 cache, and a tiny but enormously-dimensioned upload could OOM the decoder.
