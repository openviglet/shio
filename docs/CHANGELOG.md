## Block A — Headless foundation (Content Delivery API)

- **SH5** — **Per-environment keys (prod/preview).** `ShApiToken` gains an `env` ([ShApiTokenEnv](../shio-app/src/main/java/com/viglet/shio/persistence/model/token/ShApiTokenEnv.java): `PROD`/`PREVIEW`; `environment` column, `ddl-auto=update`, no migration; `null` = `PROD`). The axis is orthogonal to the SH2 `scope`: scope = *what operations*, env = *which content state*. [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) reads it, grants `ROLE_CDA_PREVIEW` for `PREVIEW` keys, and carries it in [ShApiTokenContext](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenContext.java) (new `env` component + `preview()`; back-compat 3-arg constructor defaults `PROD`). [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) replaces the hard-coded `PUBLISHED` with a per-request resolution — **`PROD` keeps the existing efficient single-state `Page` queries byte-for-byte**; **`PREVIEW` reads draft-preferred** (point lookups try `DRAFT` then `PUBLISHED` via `resolvePost`/`readStates`; listings/query/GraphQL fetch `{DRAFT,PUBLISHED}` via new `…StateIn` finders, dedup by post id keeping the `DRAFT` row, and page in memory). Driven **solely by `env`** (the SH2 `PREVIEW` *scope* stays an authz marker SH13 builds on), so there's one draft-visibility driver and REST + GraphQL (SH4) inherit it identically; the SH2 per-site allow-list still applies on every branch. `ShApiTokenAPI` persists `env`; React token editor adds an **Environment** select + description, list shows a preview badge, en/pt i18n. No-token / pre-SH5 access stays `PROD` = the SH1 behaviour. 17 tests green (`ShApiTokenFilterTest` 10 (+2), `ShCdaEnvTest` 4 (new), `ShCdaScopeTest` 3) + SH1's `ShCdaAPITest` 11 still green. **SH13** (short-lived preview tokens + in-console "preview this draft" UX) layers on this draft-visibility machinery. Spec: `docs/specs/SH5-per-environment-keys.md`.
- **SH4** — **Real GraphQL delivery schema.** [ShGraphQLSchema](../shio-app/src/main/java/com/viglet/shio/api/cda/graphql/ShGraphQLSchema.java) now builds the GraphQL schema programmatically from the content post-types (replacing the placeholder `schema.graphqls`): a `ShContent` interface carries the common post fields, each `system=0` post-type becomes an object type implementing it with a `String` field per `ShPostTypeAttr` (keyed by attr `name`), and a `ShGenericPost` fallback backs system / unmapped types (also guaranteeing the schema builds with zero content types). Names are coerced to the GraphQL grammar (invalid chars → `_`, dedup on collision). The `Query` root — `post(id)`, `postByUrl(siteId, url)`, `posts(siteId, folderId, postType, page, size)` — delegates to [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) (new `queryPosts` returns full posts with attrs; shared `queryPage`), so GraphQL **inherits SH2 per-site scoping + `PUBLISHED`-only** rather than re-implementing them — a second *shape* over the same contract, not a second contract. Served via a [ShGraphQLConfig](../shio-app/src/main/java/com/viglet/shio/api/cda/graphql/ShGraphQLConfig.java) `GraphQlSourceBuilderCustomizer.schemaFactory`. `/graphql` is now a CDA delivery surface: [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) authenticates + rate-limits it like `/api/v2/cda/**` (the SH2 GET-only gate skipped — GraphQL reads via `POST`, and the schema exposes **no `Mutation`**), and [ShSecurityConfig](../shio-app/src/main/java/com/viglet/shio/spring/security/ShSecurityConfig.java) requires `ROLE_CDA` on `POST /graphql` (was `permitAll`). Build-at-startup caveat: a new/edited post-type needs a restart to appear in the schema. Attr fields are `String` for now (strong per-widget typing awaits SH11). 8 tests green (`ShGraphQLSchemaTest` 7 incl. query-execution, `ShApiTokenFilterTest` +1 = 8) + SH1/SH2/SH3 still green. Spec: `docs/specs/SH4-cda-graphql-schema.md`.
- **SH3** — **CDA rate limiting + caching headers.** [ShCdaCacheConfig](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaCacheConfig.java) registers two servlet filters scoped to `/api/v2/cda/*`: Spring's `ShallowEtagHeaderFilter` (body-hash `ETag` + `304` on `If-None-Match`) and [ShCdaCacheControlFilter](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaCacheControlFilter.java) (`Cache-Control: public, max-age=N`, or `no-cache` when `N=0`) — both ordered after the security chain so a `401`/`403`/`429` never gets cached. [ShCdaRateLimiter](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaRateLimiter.java) is an in-memory, per-token token bucket (keyed by `ShApiToken.id`, lazy refill off a monotonic clock); [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) enforces it after auth → `429` + `Retry-After` + `X-Rate-Limit-Remaining`. All tunable via `shio.cda.*` ([ShCdaProperties](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaProperties.java): `cache.max-age-seconds` default 60; `rate-limit.{enabled,capacity,refill-tokens,refill-period-seconds}` default 120 burst / 120-per-min). **Single-instance** limiter (per-JVM budget; a Hazelcast-backed bucket is the later multi-node hardening, out of scope). 13 tests green (`ShCdaRateLimiterTest` 4, `ShApiTokenFilterTest` +1 = 7, `ShCdaCacheControlFilterTest` 2) + SH1/SH2 still green. Spec: `docs/specs/SH3-cda-rate-limit-cache.md`.
- **SH2** — **API-token scopes + per-site keys.** `ShApiToken` gains a `scope` ([ShApiTokenScope](../shio-app/src/main/java/com/viglet/shio/persistence/model/token/ShApiTokenScope.java): `READ`/`PREVIEW`/`WRITE`) and an optional `siteIds` allow-list (`@ElementCollection` → `api_token_site`; empty = all sites). [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) now **confines token auth to `/api/v2/cda/**`** (a `Key` on any other path is ignored — closes the prior any-path authentication), gates methods by scope (`READ`/`PREVIEW` GET-only, `WRITE` any), grants `ROLE_CDA_PREVIEW`/`ROLE_CDA_WRITE` accordingly, and carries scope + allow-list to the service via [ShApiTokenContext](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenContext.java) (the auth `details`). [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) enforces the allow-list at every read boundary — a disallowed site collapses to the existing 404/empty, so a per-site key can't distinguish "wrong site" from "missing". No-token / null-scope paths stay unrestricted = the SH1 behaviour (`ddl-auto=update`, no migration). React token editor adds a **Scope** select + **Site access** (all-sites switch + per-site checkboxes); list shows a scope badge; en/pt i18n. 9 tests green (`ShApiTokenFilterTest` 6, `ShCdaScopeTest` 3) + SH1's 11 still green. Spec: `docs/specs/SH2-token-scopes.md`.
- **SH1** — **Versioned, read-only CDA contract.** New `/api/v2/cda/**` namespace ([ShCdaAPI](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaAPI.java)) with 7 GET endpoints (sites, site-by-id, folder children listing, breadcrumb path, post-by-id, **post-by-url** for `[...slug]` routing, query) backed by `ShPostUnified` pinned to `PUBLISHED`. ## Block C — Composable platform primitives

- **SH26** — **Cross-DB schema-drift guard (H2 + MariaDB + PostgreSQL).** The schema is Liquibase-managed (`ddl-auto=none`), kept "agnostic" only by a *textual lint* ([ShLiquibaseChangelogAgnosticTest](../shio-app/src/test/java/com/viglet/shio/db/ShLiquibaseChangelogAgnosticTest.java)) — but the changelogs were **never actually applied** on the MariaDB/PostgreSQL engines whose drivers ship (dev + the whole suite run on H2, and tests even skip Liquibase). Three Testcontainers-backed ITs ([com.viglet.shio.tenant](../shio-app/src/test/java/com/viglet/shio/tenant)) now boot the **full Spring context** against each engine with `spring.liquibase.enabled=true` + `ddl-auto=none` — proving the full `db.changelog-master.yaml` applies, every entity maps onto the Liquibase-built schema (the `ShOnStartup` seed inserts run real DML), and `ShTenantBackfillRunner.TENANT_TABLES` resolves: [ShH2SchemaIT](../shio-app/src/test/java/com/viglet/shio/tenant/ShH2SchemaIT.java) (no Docker — runs on every `mvn verify`), [ShMariaDbSchemaIT](../shio-app/src/test/java/com/viglet/shio/tenant/ShMariaDbSchemaIT.java) + [ShPostgresSchemaIT](../shio-app/src/test/java/com/viglet/shio/tenant/ShPostgresSchemaIT.java) (`@Testcontainers(disabledWithoutDocker=true)`). They surfaced **two real cross-DB defects + one silent bug**, all fixed: (1) the generated baseline used inline **`ENUM('DRAFT','PUBLISHED')`** on `sh_post_unified` — accepted by H2/MySQL/MariaDB, **rejected by PostgreSQL** (`type "enum" does not exist`); changed to `VARCHAR(16)` (the entity is `@Enumerated(STRING) @Column(length=16)`) with `validCheckSum: ANY`, and `ENUM(` added to the forbidden-token lint so it can't return. (2) **Identifier casing** — tables are PascalCase entity names (`ShPostType`, no `@Table`) and Hibernate runs `globally_quoted_identifiers=true`, so it references them quoted/case-preserved; Liquibase created them unquoted, which **PostgreSQL folds to lower-case** → `"ShPostType"` never matched. Fixed by declaring **`objectQuotingStrategy: QUOTE_ALL_OBJECTS`** in each changelog file (set at the changelog level, not per-changeSet, so it doesn't alter checksums; repeated per file since it doesn't propagate through `include`) — Liquibase now preserves the exact case on every engine; H2/MariaDB were already tolerant. (3) **`ShTenantBackfillRunner.TENANT_TABLES`** listed **snake_case** names (`sh_post_type_attr`, …) while the real tables are PascalCase (`ShPostTypeAttr`); every name matched nothing and the runner swallowed "table not found" at `debug`, so the pre-multi-tenant backfill silently no-op'd — rewritten to the real names (incl. the previously-missing `site_webhook`).
