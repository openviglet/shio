## Block A — Headless foundation (Content Delivery API)

- **SH5** — **Per-environment keys (prod/preview).** `ShApiToken` gains an `env` ([ShApiTokenEnv](../shio-app/src/main/java/com/viglet/shio/persistence/model/token/ShApiTokenEnv.java): `PROD`/`PREVIEW`; `environment` column, `ddl-auto=update`, no migration; `null` = `PROD`). The axis is orthogonal to the SH2 `scope`: scope = *what operations*, env = *which content state*. [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) reads it, grants `ROLE_CDA_PREVIEW` for `PREVIEW` keys, and carries it in [ShApiTokenContext](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenContext.java) (new `env` component + `preview()`; back-compat 3-arg constructor defaults `PROD`). [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) replaces the hard-coded `PUBLISHED` with a per-request resolution — **`PROD` keeps the existing efficient single-state `Page` queries byte-for-byte**; **`PREVIEW` reads draft-preferred** (point lookups try `DRAFT` then `PUBLISHED` via `resolvePost`/`readStates`; listings/query/GraphQL fetch `{DRAFT,PUBLISHED}` via new `…StateIn` finders, dedup by post id keeping the `DRAFT` row, and page in memory). Driven **solely by `env`** (the SH2 `PREVIEW` *scope* stays an authz marker SH13 builds on), so there's one draft-visibility driver and REST + GraphQL (SH4) inherit it identically; the SH2 per-site allow-list still applies on every branch. `ShApiTokenAPI` persists `env`; React token editor adds an **Environment** select + description, list shows a preview badge, en/pt i18n. No-token / pre-SH5 access stays `PROD` = the SH1 behaviour. 17 tests green (`ShApiTokenFilterTest` 10 (+2), `ShCdaEnvTest` 4 (new), `ShCdaScopeTest` 3) + SH1's `ShCdaAPITest` 11 still green. **SH13** (short-lived preview tokens + in-console "preview this draft" UX) layers on this draft-visibility machinery. Spec: `docs/specs/SH5-per-environment-keys.md`.
- **SH4** — **Real GraphQL delivery schema.** [ShGraphQLSchema](../shio-app/src/main/java/com/viglet/shio/api/cda/graphql/ShGraphQLSchema.java) now builds the GraphQL schema programmatically from the content post-types (replacing the placeholder `schema.graphqls`): a `ShContent` interface carries the common post fields, each `system=0` post-type becomes an object type implementing it with a `String` field per `ShPostTypeAttr` (keyed by attr `name`), and a `ShGenericPost` fallback backs system / unmapped types (also guaranteeing the schema builds with zero content types). Names are coerced to the GraphQL grammar (invalid chars → `_`, dedup on collision). The `Query` root — `post(id)`, `postByUrl(siteId, url)`, `posts(siteId, folderId, postType, page, size)` — delegates to [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) (new `queryPosts` returns full posts with attrs; shared `queryPage`), so GraphQL **inherits SH2 per-site scoping + `PUBLISHED`-only** rather than re-implementing them — a second *shape* over the same contract, not a second contract. Served via a [ShGraphQLConfig](../shio-app/src/main/java/com/viglet/shio/api/cda/graphql/ShGraphQLConfig.java) `GraphQlSourceBuilderCustomizer.schemaFactory`. `/graphql` is now a CDA delivery surface: [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) authenticates + rate-limits it like `/api/v2/cda/**` (the SH2 GET-only gate skipped — GraphQL reads via `POST`, and the schema exposes **no `Mutation`**), and [ShSecurityConfig](../shio-app/src/main/java/com/viglet/shio/spring/security/ShSecurityConfig.java) requires `ROLE_CDA` on `POST /graphql` (was `permitAll`). Build-at-startup caveat: a new/edited post-type needs a restart to appear in the schema. Attr fields are `String` for now (strong per-widget typing awaits SH11). 8 tests green (`ShGraphQLSchemaTest` 7 incl. query-execution, `ShApiTokenFilterTest` +1 = 8) + SH1/SH2/SH3 still green. Spec: `docs/specs/SH4-cda-graphql-schema.md`.
- **SH3** — **CDA rate limiting + caching headers.** [ShCdaCacheConfig](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaCacheConfig.java) registers two servlet filters scoped to `/api/v2/cda/*`: Spring's `ShallowEtagHeaderFilter` (body-hash `ETag` + `304` on `If-None-Match`) and [ShCdaCacheControlFilter](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaCacheControlFilter.java) (`Cache-Control: public, max-age=N`, or `no-cache` when `N=0`) — both ordered after the security chain so a `401`/`403`/`429` never gets cached. [ShCdaRateLimiter](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaRateLimiter.java) is an in-memory, per-token token bucket (keyed by `ShApiToken.id`, lazy refill off a monotonic clock); [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) enforces it after auth → `429` + `Retry-After` + `X-Rate-Limit-Remaining`. All tunable via `shio.cda.*` ([ShCdaProperties](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaProperties.java): `cache.max-age-seconds` default 60; `rate-limit.{enabled,capacity,refill-tokens,refill-period-seconds}` default 120 burst / 120-per-min). **Single-instance** limiter (per-JVM budget; a Hazelcast-backed bucket is the later multi-node hardening, out of scope). 13 tests green (`ShCdaRateLimiterTest` 4, `ShApiTokenFilterTest` +1 = 7, `ShCdaCacheControlFilterTest` 2) + SH1/SH2 still green. Spec: `docs/specs/SH3-cda-rate-limit-cache.md`.
- **SH2** — **API-token scopes + per-site keys.** `ShApiToken` gains a `scope` ([ShApiTokenScope](../shio-app/src/main/java/com/viglet/shio/persistence/model/token/ShApiTokenScope.java): `READ`/`PREVIEW`/`WRITE`) and an optional `siteIds` allow-list (`@ElementCollection` → `api_token_site`; empty = all sites). [ShApiTokenFilter](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenFilter.java) now **confines token auth to `/api/v2/cda/**`** (a `Key` on any other path is ignored — closes the prior any-path authentication), gates methods by scope (`READ`/`PREVIEW` GET-only, `WRITE` any), grants `ROLE_CDA_PREVIEW`/`ROLE_CDA_WRITE` accordingly, and carries scope + allow-list to the service via [ShApiTokenContext](../shio-app/src/main/java/com/viglet/shio/spring/security/auth/ShApiTokenContext.java) (the auth `details`). [ShCdaService](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaService.java) enforces the allow-list at every read boundary — a disallowed site collapses to the existing 404/empty, so a per-site key can't distinguish "wrong site" from "missing". No-token / null-scope paths stay unrestricted = the SH1 behaviour (`ddl-auto=update`, no migration). React token editor adds a **Scope** select + **Site access** (all-sites switch + per-site checkboxes); list shows a scope badge; en/pt i18n. 9 tests green (`ShApiTokenFilterTest` 6, `ShCdaScopeTest` 3) + SH1's 11 still green. Spec: `docs/specs/SH2-token-scopes.md`.
- **SH1** — **Versioned, read-only CDA contract.** New `/api/v2/cda/**` namespace ([ShCdaAPI](../shio-app/src/main/java/com/viglet/shio/api/cda/ShCdaAPI.java)) with 7 GET endpoints (sites, site-by-id, folder children listing, breadcrumb path, post-by-id, **post-by-url** for `[...slug]` routing, query) backed by `ShPostUnified` pinned to `PUBLISHED`. Spec: `docs/specs/SH1-cda-read-contract.md`.

## Block B — JavaScript-for-pages DX

- **SH63** — **Post-types DSL core (`@viglet/shio-model`).** The authoring inverse of SH11's model→types codegen: a pure, zero-dependency ESM workspace package (sibling to `@viglet/shio-client`) that lets a JS dev write the content model as **typed TypeScript** and compile it to the canonical SH16 `ShPostTypeDef` JSON the admin API already consumes. **Builders** ([builders.ts](../shio-model/src/builders.ts)): `postType(name, opts)` + one factory per the 14 widgets (`text`/`textArea`/`htmlEditor`/`checkBox`/`comboBox`/`date`/`hidden`/`multiSelect`/`aceJs`/`aceHtml`/`contentSelect`/`file`/`relator`/`tab`), each returning a `ShPostTypeAttrDef`; ordinals auto-assigned 1-based by array position (override via `ordinal`), `system` always `false` (system types stay backend-owned). Settings-bearing factories take **typed** options (`comboBox` *requires* `choices` — a missing one is a `tsc` error, not a `push` 400), so `tsserver` gives autocomplete + compile-time validation with no custom VSCode extension. **widgetSettings codec** ([widget-settings.ts](../shio-model/src/widget-settings.ts), the heart of the package): encodes the ergonomic typed settings to the *exact* legacy wire string — `choices: {tech:"Technology"}` → `"{\"choices\":\"tech: Technology\\nbiz: Business\",\"allowNull\":1}"`, `file`/`contentSelect`/`multiselect`/`relator` single-key wrappers, empty settings → `null` (never the string `"null"`) — with a **symmetric decoder** for every encoder (`decodeChoices`/`decodeFile`/`decodeContentSelect`/`decodeMultiSelect`/`decodeRelator`) so SH64 can scaffold a starter `.ts` from `pull`ed JSON. **Serialization** ([serialize.ts](../shio-model/src/serialize.ts)): `normalizeDef`/`serializeDef`/`toDef` reimplement SH16's canonical normalization (fixed key order, fields sorted by ordinal-then-name, stable defaults, trailing newline) so the compiled JSON is **byte-identical** to a hand-written `shio/post-types/*.json` — one serialization contract, the DSL can never disagree with the bytes that drive `push`'s diff. **Tests:** 15 `node:test` green ([builders.test.mjs](../shio-model/test/builders.test.mjs)) — widget-by-widget codec round-trips, ordinal assignment (auto + explicit-preserved), relator/tab nesting, null/garbage-tolerant decoders, and the §8.1 acceptance anchor: byte-identical serialization vs a hand-checked golden fixture ([news.golden.json](../shio-model/test/news.golden.json)). Wired into the root `pnpm test`. SH64 (CLI compile step) / SH65 (drift guard) / SH66 (console lock) build on this. Spec: `docs/specs/SH62-post-types-dsl.md` §4.

- **SH40** — **Resize/crop transform pipeline (Thumbnailator/ImageIO).** Plugs the real engine into the SH39 seam: [ShThumbnailatorImageTransformPipeline](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShThumbnailatorImageTransformPipeline.java) is the `@Primary` [ShImageTransformPipeline](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShImageTransformPipeline.java), so the `/api/v2/staticfile/{id}` controller and the `/file_source/**` resource transformer now actually transform images (the SH39 `ShNoOpImageTransformPipeline` stays as the non-primary fallback). Each [ShImageCropMode](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShImageCropMode.java) maps to a Thumbnailator recipe: **FIT** (default) `size(w,h)` fits within preserving aspect (a single dimension scales by that axis); **FILL** `size(w,h).crop(CENTER)` covers then centre-crops to exactly `w×h`; **CROP** `sourceRegion(CENTER,w,h).scale(1.0)` centre-crops a region with no scaling; **SCALE** `size(w,h).keepAspectRatio(false)` stretches to exactly `w×h`. **Scope = resize/crop only:** the output is always re-encoded in the **source** format (jpeg/png/gif/bmp resolved from content-type then extension) — honouring `?format=` (webp/avif negotiation) is SH41, so a format-only request (no `w`/`h`) returns empty (→ original). - **SH42** — **Image-transform result cache (disk/memory, ETag, tenant-aware).** A transform (decode → resize/crop → re-encode, SH40/SH41) is pure but expensive, and a given `source + ?w=&h=&format=&crop=` always yields the same bytes — so memoise them. **Caching decorator:** new [ShCachingImageTransformPipeline](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShCachingImageTransformPipeline.java) is now the `@Primary` [ShImageTransformPipeline](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShImageTransformPipeline.java) (the SH40 [ShThumbnailatorImageTransformPipeline](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShThumbnailatorImageTransformPipeline.java) drops `@Primary` and becomes the injected delegate), so **both** delivery routes — the `/api/v2/staticfile/{id}` controller and the `/file_source/**` resource transformer, which already inject the primary bean — go through the cache transparently. **Store:** [ShImageTransformCache](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShImageTransformCache.java) is a size-bounded in-memory LRU (`Collections.synchronizedMap` over an access-ordered `LinkedHashMap` with `removeEldestEntry`) in front of a disk cache rooted at [ShImageCacheProperties](../shio-app/src/main/java/com/viglet/shio/property/ShImageCacheProperties.java)`.path` (`shio.image-cache.path`, default `store/image_cache`; `.enabled`, `.max-memory-entries`). The **key** is a hex SHA-256 over `tenant | filename | lastModified | length | w | h | format | crop` — the source identity is the HTTP weak-validator triple (name + mtime + size), so a re-upload that changes the bytes lands on a fresh key (old entries orphan; disk pruning is left to ops, not done here). Each entry is two files: `<hash>` (bytes) + `<hash>.ct` (content type); disk I/O is best-effort — a read/write failure degrades to a miss / no-store and is logged, never thrown, so a broken cache can't break delivery. **Tenant-aware (SH22):** the current [ShTenantContext](../shio-app/src/main/java/com/viglet/shio/tenant/ShTenantContext.java) tenant (default `shio`) is the first key component **and** the disk sub-directory (`<root>/<tenant>/<hash>`), so tenant A and B never share a cached entry or an ETag even for an identical source path + params. **ETag / 304:** the key doubles as a stable strong ETag stamped onto the [ShImageTransformResult](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShImageTransformResult.java) (new third record component + back-compat two-arg ctor + `withEtag`); the controller emits `ETag` and answers `If-None-Match` with `304 Not Modified`, and the public `/file_source/**` path does the same via a `setEtagGenerator` on the resource handler ([ShStaticResourceConfiguration](../shio-app/src/main/java/com/viglet/shio/spring/ShStaticResourceConfiguration.java)) reading the ETag off the SH41 [ShImageTransformResourceTransformer](../shio-app/src/main/java/com/viglet/shio/api/staticfile/transform/ShImageTransformResourceTransformer.java)`.ShTransformedImageResource`. **Empty (serve-original) results are never cached** — a decline (non-image, writer-less target, I/O failure) must stay re-evaluable so a later transformable upload at the same id isn't poisoned by a negative entry; a disabled cache is a thin pass-through that stamps no ETag. 12 new tests (8 [ShImageTransformCacheTest](../shio-app/src/test/java/com/viglet/shio/api/staticfile/transform/ShImageTransformCacheTest.java) — key stability/variance/tenant-scoping, memory+disk round-trip, cross-instance disk read, tenant-prefixed layout;
