# Viglet Shio: consistency with viglet.org

Review date: 2026-11-08. Scope: analysis and roadmap planning only.

## Verdict

Keep the dedicated product site. Its purpose is to explain and demonstrate the product and guide adoption; the hub introduces the portfolio and its relationships. The sites should share brand and interaction rules while retaining distinct product evidence. No Next.js migration or merged documentation platform is needed to achieve that consistency.

The product sites currently resemble one another more than the revised hub. All three still use dark decorative heroes, gradient headings, metadata chips, highlighted navigation pills and Plus Jakarta Sans as body text. The hub uses a quieter neutral layout, typographic metadata and Inter body text. Product colors are already coherent: blue for Viglet Turing, teal for Viglet Dumont and violet for Viglet Shio. Keep them.

## Evidence and interpretation

The strongest product story is one content engine usable through the console, coding agents, repository files and delivery APIs. Preserve all four, with human authoring visible from the beginning. The scripted sessions and finished-site showcase are useful, but must keep their actual evidence level visible.

The home is especially extensive: it combines product discovery with design laws, token budgets, protocol errors and verification internals. These deserve depth pages, not equal prominence in the first-time evaluation path. The special Claude Code navigation pill competes with the console-first explanation. Keep the supported plugin available while giving the four entry paths a clear hierarchy.

The hub describes optional indexing in Viglet Turing, while the public site's content mainly offers a footer link. `docs/agents/turing.md` confirms indexing is off by default and requires explicit configuration and routing. Explain that optional relationship without implying an LLM in the CMS, an obligatory Viglet Dumont dependency or an implemented Codex plugin.

Get started leads to the docs overview, while the hero primarily scrolls to a choice of paths. Changelog points to the internal GitHub ledger. Distinguish exploration, installation and user release history. Existing SH1342 owns the hosted-demo gap and is not duplicated here.

This checkout had unrelated work in progress, including changes to the three governed documentation files. This review only appended its own tasks through Roadkeep and adds this report; no pre-existing changes were reverted or committed.

The mobile header keeps only the product mark; its accessible name remains present. The task is to preserve visible product identification when adapting the layout, not to report a missing accessible name. Full names already appear in desktop logos, but that alone does not satisfy the owner's whole-site naming decision.

## Shared design contract

- Always use Viglet Turing, Viglet Dumont and Viglet Shio in visitor-facing language and entity metadata. Preserve commands, packages, routes, technical identifiers and historical records.
- Align typography roles, readable content widths, heading hierarchy, spacing, borders, buttons, focus treatment and theme behavior with the hub. Use the shared design system where its released exports fit.
- Replace decorative chips with plain labels, separators or navigation links. Genuine selected filters, tabs and state controls retain their interaction semantics.
- Reuse hero structure across marketing pages. Documentation keeps its reading layout, search and sidebar while sharing identity, tokens and navigation destinations.
- Separate product exploration, installation, documentation, source code and release history. Keep Source on the product repository and Roadmap distinct from user release notes.
- Preserve truthful product demonstrations. Scripted, illustrative, recorded and live experiences must remain distinguishable.

## Validation performed

Read source in `shio-site`, the product documentation project, navigation/link data, hero components, page composition and relevant product guidance. Inspected live pages using Playwright with a fresh Chrome profile and screenshots.

The home was checked at 1440 and 390 CSS pixels. The docs overview was checked at 1440 and the getting-started introduction at 390. All four checks returned HTTP 200, with no document-wide overflow or JavaScript page errors recorded. Mobile home document height was 35,933 CSS pixels at a 390 by 960 viewport; this is an observation of content volume, not a performance or conversion score.

Representative solution and feature pages were also sampled and screenshots inspected. Some additional navigations encountered connection resets; these were not classified as site defects. This was not an exhaustive crawl, accessibility certification, installation test or analytics study. Cookie consent was not accepted to enable measurement. No product, infrastructure or publishing change was made.
