WHAT CHANGED, BY PIN
1
One toolbar, on the list. Filter, import, sort, view and columns sit together. The empty band that held only “Columns” is gone.
2
Identity before text. Initials in a hue derived from the name, so a site is recognised before it is read. The address is the one an agent writes.
3
Description is a second line, not a column. One site in 23 has one; it held half the width.
4
Pages by state. The number that says whether a site is alive. An empty site says “No pages yet”.
5
Last change, relative and attributed. “2 days ago · claude agent”; the absolute date is the tooltip. Sorted by this, newest first.
6
Verbs on hover and focus. Preview, then ··· for Open, Export and Delete. The row itself opens the site.
7
The page scrolls, the header sticks. No fixed-height table with its own scrollbar inside a scrolling page.
WHAT THIS DECIDES
Two of the four columns are not in the sites listing today: pages by state and the last change with its author. Both have to arrive in the listing’s one read — a grouped count and the newest audit row per site — never as a request per row. That is the line between a console change and a backend one. Pins 1 and 7 are the design system’s list page, so they change Turing too.
NOT CHOSEN — THE SAME FIVE COLUMNS, DENSER
Shrinking padding and font keeps every column and fixes “tight” by making it tighter. The defect was proportion: a mostly empty Description column holding half the width, and a date stranded a screen away from its name.
