shio — the Shio CMS CLI

Usage:
  shio <command> [options]
  shio <command> --help      That command's own flags

Commands:
  init [name]    Scaffold a Next.js site wired to the Shio CDA
  context        The agent context pack: model + sitemap + conventions, in one call
  surfaces       What the console offers, and how to do each from here
  mcp            Bridge stdio to this instance's MCP endpoint
  resolve <addr> Resolve a content address (post:/folder:/site:/id:) to its object
  find           Posts by site/folder/type/state/locale/date/author, as addresses
  impact <addr>  What a change to this template would affect: layouts, types, page counts
  apply [file]   Plan/apply a desired-state content document, or a package
  import <file>  Clone an SH68 exchange package (.zip) into this instance
  export site:<n> Hand a whole site to another instance, as a zip
  blueprints     List the appliable starting points (blueprints <name> for its parameters)
  marketplace    Browse and install blueprint packages from a catalogue
  publish [addr] Make drafts live, or take live pages down
  gate           The checks a site runs before content goes live (run, list)
  verify         Lint the content and its routes; exits non-zero on an error
  index          Which sites reach the search index, and push one there again
  redirects      Which old addresses still answer, and which ones a rename left 404ing
  changes        What changed, with a cursor to resume from
  review         What an agent run left for a person (list, show, decide)
  notes          What a curator is still asking for
  report         What changed, preview links, open questions
  remember       Write down a decision for the next session
  digest <page>  Structural digest of one page: outline, landmarks, links, images
  preview <file> A content file's page, rendered before you push it
  share <addr>   An expiring link to one page; --list, --revoke
  snapshot <page> PNG of a page, and whether it looks different (playwright)
  audit <page>   What is wrong with a rendered page, as text with a selector each
  annotations <page>
                 The props a page emits vs the fields its types declare
  judge          Run verify/diff (audit/snapshot on request) and answer once
  site           List the sites; site rm --scratch sweeps the disposable ones
  clone <url>    Capture a site that already exists: an inventory, and no content
  propose        Which captured blocks could become sections, and what each loses
  convert        Apply the accepted conversion plan: sections, theme and scripts, as DRAFT
  diff           Compare a replica with its capture, what is live, or a revision
  versions <addr> What this page has been: one line per captured revision
  rollback <addr> Put a revision back into the draft
  schedule       What goes live or comes down, in time order
  post set       Change some fields of a post, refused if it moved
  pull           Pull post-types into ./shio/post-types/*.json (--content for pages)
  push           Apply local post-types back to Shio, or the content tree
  build          Compile local DSL/JSON post-types to canonical JSON
  types          Generate a TypeScript .d.ts from the live post-types (CDA token)
  dev            Types, dev server, model watch (--content syncs shio/content/**)
  deploy         push (apply) then types
  assets         assets prune: what nothing references, and what deleting it frees
  patterns       Capture a page's sections as a file, and place them in another page
  status         Counts, what is waiting for a person, and what just happened
  doctor         Instance, build stamp, drift, sites, content tree

Connection:
  --url <baseUrl>      Shio base URL          (env SHIO_URL, default http://localhost:2710)
  --user <user>        Console user           (env SHIO_USER)        [pull/push/deploy]
  --password <pass>    Console password       (env SHIO_PASSWORD)    [pull/push/deploy]
  --token <token>      CDA token              (env SHIO_CDA_TOKEN)   [types/dev]

Common options:
  --intent <sentence>  What this run is for
  --dir <dir>          Post-types directory   (default shio/post-types) [pull/push/build]
  --out <file>         Output path            (.d.ts for types; dir for pull/build)
  --dry-run            push/apply: print the plan, change nothing
  --check              push/apply: exit non-zero if the plan is non-empty
  --prune              push: delete remote types absent locally (never system types)
  --no-read-cache      Read the instance unconditionally (see shio/.shio/read-cache.json)
  -h, --help           Show help
