shio clone <url> — capture a site that already exists, and write no content

Walks one origin and records what it found in shio/.shio/source-inventory.json. That file
is the only thing written unless you ask for more, which is the promise every later phase
rests on: read the inventory before anything else happens.

  --depth <n>              How deep to follow internal links (default 3; 0 = the seed page)
  --max-pages <n>          Ceiling on pages fetched (default 200); a cut is recorded, so a
                           partial capture can never read as a complete one
  --markup                 Keep each page's HTML — what shio propose computes from
  --assets                 Download the bytes the inventory names (needs --site)
  --site <name>            With --assets: whose asset tree the bytes go under
  --max-assets <n>         With --assets: ceiling on downloads (default 500)
  --max-asset-bytes <n>    With --assets: skip anything larger (default 26214400)
  --scripts                With --assets: take this site's own <script src> too. What is
                           dropped is named in the report, flag or no flag
  --refresh                Re-check the capture in --out instead of crawling, conditionally
                           on each page's recorded ETag. Needs --markup. Does NOT walk for
                           new pages — a new link is named in the notes, never followed
  --render                 Drive a browser, for a page that renders itself (needs
                           playwright). Without it the crawl reads what the server sent
  --ignore-robots          Crawl anyway; recorded in the inventory
  --delay <seconds>        Wait between requests (default: the site's own Crawl-delay)
  --timeout <ms>           Per-page timeout with --render (default 30000)
  --no-progress            Write only what was asked for. By default the crawl also writes
                           shio/.shio/clone-status.json (where it is now; fixed size) and
                           clone-progress.jsonl (one line per page or asset)
  --out <file>             Inventory path (default shio/.shio/source-inventory.json)
  --json                   The inventory on stdout instead of the report
  --url <url>              The site to capture, when no positional is given. The ONE command
                           where --url is the target, not the instance: clone never talks to
                           a Shio instance

Examples:
  shio clone https://acme.example.com --markup
  shio clone https://acme.example.com --markup --assets --site Acme --depth 2

  Re-check it later without paying for the crawl again. No URL: the capture says where
  the site is, so a mistyped one cannot refresh against a different host:
    shio clone --refresh

  A long one, followed rather than watched — the shape for a real site, where --render can
  spend the per-page timeout on every page of a 200-page ceiling:
    shio clone https://acme.example.com --render --assets --site Acme > clone.log 2>&1 &
    cat shio/.shio/clone-status.json      # where it is; safe to repeat, never grows
