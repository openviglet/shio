# Writing a Shio docs page

**Apply `docs-writing` first.** The shared skill (`~/.claude/skills/docs-writing`) has the
method, the page templates and the style guide; this file has only what is specific to
Shio, and wins where the two differ. Generated by `docs-setup` (SH1402); a gap here is
fixed in `docs-setup`, then regenerated.

Where a feature is documented, and whether it needs a page at all, is decided first by
`shio-roadmap-docs` (§ end-user documentation). Whether a page matches the code is
`shio-docs-sync`. This skill is how the page is written.

## Where the pages are

- Pages: `shio-site/docs/src/content/docs/`, `.md`, or `.mdx` when a page uses components.
  `COVERAGE.md` sits beside them and is not a page (`content.config.ts` excludes it).
- Navigation: the `sidebar` in `shio-site/docs/astro.config.mjs`, grouped under four hubs
  by who does the job: `agent-builds-it.mdx`, `curator-approves-it.mdx`,
  `cda-delivers-it.mdx`, `run-it.mdx`. A new page needs a sidebar row and a card on its
  hub, or it builds as an unlisted route nobody reaches.
- A hub's landing text is what a block's changes usually move; a per-feature edit rarely
  touches it, so check it whenever a page's opening promise changes.

## Framework components (Starlight)

- Steps: `<Steps>` around an ordered list; callouts: `:::note`, `:::tip`, `:::caution`,
  `:::danger`; tabs: `<Tabs><TabItem label>`; cards: `<CardGrid><LinkCard>`; keys:
  `<kbd>Ctrl</kbd>`.
- Components need `.mdx` and an import from `@astrojs/starlight/components`. Renaming
  `.md` to `.mdx` keeps the route; `docs-links.test.mjs` reads both.

## Product name and links

- The product is **Viglet Shio** in prose; **Shio** after the first mention on a page is fine.
- Internal links are root-absolute `/docs/<slug>/#anchor`, never `https://shio.viglet.org/docs`.
- Public code links point at `openviglet/shio`.

## Glossary

| Term | Means | Avoid |
|---|---|---|
| post | Any content item in Shio | entry, article, document |
| post type | The schema a post follows | content type (unless quoting the console's **Content type** filter, or a MIME type) |
| section | A post composed into a page by its layout | block, component (as a content term) |
| page | A post a site serves at a friendly URL | |
| site, folder | Where posts live; a folder belongs to one site | directory |
| draft / publish | The unpublished row, and the explicit act that makes it live | save live, push live |
| curator | The person who reviews and approves | the human, the user (as an actor) |
| agent | The coding agent driving MCP, files or the API | the AI, the bot |
| Universal Editor | Editing on the rendered page | visual editor, WYSIWYG |
| layout, region, theme | The page structure posts are rendered through | |
| blueprint, pattern | An appliable starting point; a captured set of sections | recipe, snippet |
| review queue | Where agent changes wait for a curator | inbox |
| friendly URL | A post's address segment | slug (outside code) |
| Content Delivery API (CDA) | The read API a front end uses | delivery endpoint |

## House style that differs from `docs-writing`

- **No em dash** in published prose (SH929; held for the site by `ai-writing.test.mjs`,
  and for these pages by the docs-style lint).
- A person is named by the role, not "the human" (SH705, `actor-vocabulary.test.mjs`).
- Numbers that the build measures (token figures, tool counts) are never typed by hand;
  `shio-roadmap-docs` names the generated sources.

## Coverage

Every user-facing ship records its verdict in `COVERAGE.md` (✅ / 🧩 / 🔒, with the page and
anchor) in the same commit as the page, then `pnpm run coverage:mirror`. Keep an anchor
that COVERAGE or another page links to, or update the link in the same change.

## Gates, in order

1. `pnpm --filter shio-site test`: includes `scripts/docs-style.test.mjs` (the
   mechanical style rules, SH1401) and `scripts/docs-links.test.mjs` (every `/docs` link
   and `#anchor` resolves).
2. `pnpm test`: the JS gate; read `shio-js-test.log`.
3. `pnpm conformance:docs`: names, versions and coverage against the code; read
   `shio-conformance-docs.log`.
4. `pnpm --filter shio-site build`: Starlight fails on an unknown sidebar id.

Never pipe a gate into `grep` (agents.md, SH354/SH788): redirect, then read the log.

## Debt

`BASELINE` in `shio-site/scripts/docs-style.test.mjs` lists the pages that still break a
style rule. When you rewrite a page, remove its entries in the same commit; the lint fails
on an entry that is paid. The rewrites are filed in roadkeep Block R (SH1403 to SH1409,
largest pages first).
